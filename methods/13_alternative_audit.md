## Validation issue to fix before larger experiments

The stack in `build_notebook.py` constructs first-level OOF and neighbor features using five folds, then validates the second-level model on those **same** folds. During one second-level validation fold, its training rows' OOF models and neighbor features can depend on labels from that validation fold. This makes the second-level CV estimate partially dependent on held-out labels. Use an outer CV split; regenerate all first-level OOF and neighbor features using only that outer split's training labels, train the stack there, and evaluate on its untouched validation rows. Cut-point class shares should likewise come from the outer training rows. Retain the current folds for comparability, then add another seed or a group-aware stress test.
