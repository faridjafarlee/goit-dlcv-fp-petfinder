## Що робить ноутбук

1. Шукає таблиці в `/kaggle/input/*` (локально в `data/`). Train визначає як таблицю з `PetID` і ціллю, тест як таблицю з `PetID` і назвою `test` / `valid` / `val`; якщо кандидатів кілька, обирає за збігом із `sample_submission`. Перевіряє колонки ID, цілі й тексту (приймає й альтернативні назви: `id`, `target`, `description`…), дублікати й цілочисельність цілі. Класи бере з даних, тож працює і з 0-4, і з 1-4. Коли чогось бракує, зупиняється з поясненням. Без даних змагання переходить у проксі-режим.
2. Один раз проходить по папці даних і зіставляє фото з `PetID` за схемами `<PetID>-<n>.jpg`, `<PetID>.jpg` або `<PetID>/*.jpg`. У режимі змагання без жодного фото ноутбук зупиняється, бо потрібні і фото, і текст.
3. В EDA показує розподіл цілі, довжину описів, кількість фото на тварину і середню ціль за довжиною опису й кількістю фото.
4. Будує ознаки:
   - табличні: усі спільні колонки train і test; категорії як `category`, для частих категорій ще й частота; `RescuerID` як лічильник оголошень волонтера; ім'я (довжина і чи воно є); кількість фото;
   - текст: 10 статистик; TF-IDF слів (n-грами 1-2) і символів (2-5) → TruncatedSVD 32 + 32;
   - текст (прапорець `USE_TEXT_EMB`): `paraphrase-multilingual-MiniLM-L12-v2`, mean pooling → PCA 32;
   - фото (`USE_IMAGES`): EfficientNet-B0 ImageNet (GAP, 1280) для перших `MAX_IMAGES_PER_PET = 5` фото, середнє по тварині → PCA 32; якщо фото немає або всі биті, ставить NaN і `img_missing`; розміри фото. Бекбон можна змінити: `densenet121`, `resnet50` або будь-яка CLIP / SigLIP з Hugging Face (`'hf:<id або шлях>'`). Батчі рахуються на GPU, якщо він є (cuda → mps → cpu);
   - JSON sentiment / metadata, якщо такі папки є (як в оригіналі).
5. Навчає LightGBM-регресію (якщо LightGBM немає, то sklearn HistGradientBoosting) на 5-fold StratifiedKFold або StratifiedGroupKFold за `RescuerID`, з 3 seed-ами. OptimizedRounder тут є детермінованим покоординатним пошуком порогів під QWK на OOF. Ноутбук рахує три QWK (типові пороги, пороги на всіх OOF, вкладений, без витоку) і наївні бейзлайни. Optuna вмикається прапорцем (`USE_OPTUNA`, TPE з seed); є абляція за групами ознак.
6. Для фіналу навчає моделі на всьому train (дерев = середнє з фолдів × 1.15) × 3 seed-и й усереднює їх з моделями фолдів (`FINAL_PREDICTION = 'blend'`). Далі пороги з OOF, обрізання до діапазону класів, `submission.csv` з заголовком `PetID,AdoptionSpeed` у порядку `sample_submission`, SHA-256 файлу, `run_info.json` (параметри, пороги, seed-и, версії) і `EXPECTED_SUBMISSION_SHA256` для перевірки відтворення.

AutoML-бібліотек немає. Використано pandas, numpy, scikit-learn, PyTorch + torchvision, transformers, LightGBM, опційно Optuna. Токенів і ключів у ноутбуці немає, локальних абсолютних шляхів у виводах теж.

## Результати на проксі-даних (це не дані змагання)

Проксі-дані взято з таблиці PetFinder з курсу ML (`machine-learning-fundamentals/datasets/mod_04_topic_08_petfinder_data.csv.gz`): 11 537 тварин, без фото, без PetID і без RescuerID, ціль 0-4. 20 % (2 308) відкладено як псевдо-тест. На даних змагання числа будуть інші.

| | QWK |
|---|---|
| OOF, типові пороги 0.5/1.5/2.5/3.5 | 0.346 |
| OOF, пороги підібрані на всіх OOF (оптимістично) | 0.446 |
| OOF, вкладений підбір порогів (без витоку) | 0.438 |
| псевдо-тест (відкладені 20 %), фінальний `blend` + пороги з OOF | 0.424 |
| наївні бейзлайни (завжди найчастіший клас 2 / округлене середнє 2) | 0.000 |

OOF RMSE 1.036 (прогноз середнім дає 1.173); QWK по фолдах від 0.432 до 0.468. Абляція (1 seed, вкладений QWK): лише табличні 0.399 → + статистики й TF-IDF 0.432 → + ембединги MiniLM 0.426. Отже, на проксі-даних трансформерні ембединги не допомогли, а TF-IDF допоміг. На даних змагання це треба перевірити за таблицею абляції. SHA-256 проксі-сабміту `587fe3f5…afa` збігся в трьох незалежних запусках (двічі з перерахунком ембедингів на MPS).

## Як адаптувати CONFIG до даних змагання

Найчастіше нічого міняти не треба. Після `Run All` перевірте вивід розділу 1:
`Режим: ЗМАГАННЯ`, знайдені `train` / `test` / `sample`, `ID = 'PetID'`, `ціль = 'AdoptionSpeed'`, `текст = 'Description'`, `Класи цілі: [...]`, `Тварин з фото: train …%, test …%` (має бути близько до 100 %).

Якщо щось не так:

| Проблема | Що змінити |
|---|---|
| вибрано не ті CSV | `TRAIN_CSV`, `TEST_CSV`, `SAMPLE_SUB_CSV` (повні шляхи `/kaggle/input/...`) |
| інші назви колонок | `ID_COL`, `TARGET_COL`, `TEXT_COL`, `GROUP_COL` |
| фото не зіставились (0 % або мало) | подивитися кілька назв файлів і змінити `IMAGE_NAME_REGEX` (напр., для `PetID_1.jpg`: `r'^(?P<pet_id>.+?)_(?P<n>\d+)\.jpe?g$'`) або вказати `TRAIN_IMAGE_DIR` / `TEST_IMAGE_DIR`. Схеми `PetID.jpg` і `PetID/*.jpg` підхоплюються самі |
| є `RescuerID`, але тест поділено випадково (ті самі волонтери в train і test) | порівняти CV з лідербордом; можливо, `GROUP_COL = None` дасть ближчу до LB оцінку |
| числові коди, які насправді категорії | додати назву колонки в `CATEGORICAL_HINTS` |
| повільно на CPU | `MAX_IMAGES_PER_PET = 1` або `2`, `IMG_BATCH_SIZE = 32` |
| ембединги тексту не допомагають (абляція) | `USE_TEXT_EMB = False` або інша модель у `TEXT_MODEL` |

## Запуск на Kaggle

1. На сторінці змагання: `Code → New Notebook` (дані підключаться самі), далі `File → Import Notebook` і завантажити `petfinder_final_template.ipynb`. Або у своєму ноутбуці: `Add Input → Competitions`.
2. У `Settings`: `Accelerator: GPU T4 x2` (або P100); `Internet: On`. Інтернет потрібен для ваг EfficientNet з download.pytorch.org і моделі MiniLM з Hugging Face; вмикається він лише після верифікації телефону. torch, torchvision, transformers, lightgbm і scikit-learn в образі Kaggle вже є. Якщо Optuna немає, `!pip install -q optuna`.
3. Без інтернету ваги треба підключити як Kaggle Dataset (`Datasets → New Dataset`, приватний):
   - EfficientNet-B0: файл `efficientnet_b0_rwightman-7f5810bc.pth` (лежить локально в `~/.cache/torch/hub/checkpoints/` або за адресою `https://download.pytorch.org/models/efficientnet_b0_rwightman-7f5810bc.pth`) → у ноутбуці `Add Input → Datasets → свій` → `IMAGE_WEIGHTS_PATH = '/kaggle/input/<dataset>/efficientnet_b0_rwightman-7f5810bc.pth'`;
   - текстова модель: локально `python -c "from huggingface_hub import snapshot_download as s; s('sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2', local_dir='minilm')"`, завантажити папку `minilm` як Dataset → `TEXT_MODEL = '/kaggle/input/<dataset>/minilm'`;
   - SigLIP / CLIP так само: `IMAGE_BACKBONE = 'hf:/kaggle/input/<dataset>/<папка моделі>'`.
4. `Run All`, перевірити вивід розділу 1 (див. вище), потім `Save Version → Save & Run All (Commit)`, щоб виводи й файли лишились у версії. `submission.csv` з'явиться в `/kaggle/working` (вкладка `Output` версії). Звідти його можна подати або завантажити й подати через `Submit Prediction` на сторінці змагання.
5. Час на Kaggle я не міряв. EfficientNet-B0 без донавчання робить один прохід по фото: на GPU це хвилини, на CPU десятки хвилин. Квота GPU 30 год/тиждень, тож на дрібні експерименти її краще не витрачати.

Особливість macOS (лише для локального запуску): torch, LightGBM і scikit-learn мають різні копії libomp. Якщо torch першим запустить CPU-потоки, LightGBM падає з segfault (тут це перевірено). Тому ноутбук імпортує LightGBM до torch, а на macOS ставить `torch.set_num_threads(1)`. На Kaggle (Linux) цієї проблеми немає.

## Відтворюваність (критерій прийняття)

- Фіксовані `SEED = 42` і `MODEL_SEEDS = [42, 7, 2026]`. LightGBM з `deterministic=True`, `force_row_wise=True`, `N_THREADS = 4`. Пороги шукає детермінований пошук, SVD / PCA мають фіксований `random_state`. cuDNN у детермінованому режимі. Ембединги кешуються на диск і перед PCA округлюються до 1e-4, щоб шум GPU не міняв результат.
- Після останнього сабміту скопіювати SHA-256 з виводу розділу 5 (або з `run_info.json`) у `EXPECTED_SUBMISSION_SHA256`, запустити ще раз на тому самому типі GPU і переконатися, що ноутбук друкує «Збігається з поданим файлом: ТАК». Саме цю версію завантажувати в LMS.
- Якщо використовувалась Optuna, вставити надруковані параметри в `TUNED_PARAMS`, поставити `USE_OPTUNA = False` і перезапустити. Сабміт робити з цього запуску, щоб код відтворював поданий файл без повторного пошуку.
- Зараз у розділі 6 ноутбука проксі-числа (з позначкою). Перед здачею їх треба замінити числами з запуску на даних змагання або видалити проксі-текст.

## Ідеї, як підняти QWK

- Ембединги фото з CLIP / SigLIP / SigLIP 2 замість EfficientNet: `IMAGE_BACKBONE = 'hf:google/siglip2-base-patch16-224'` (перевірено: 768-вимірні вектори). За конспектом практики ментора, одногрупник мав 0.77 з замороженим SigLIP 2, у ментора було ≈ 0.67-0.69. Брати моделі з фіксованою роздільністю (`patch16-224/256/384`), не `naflex`. Можна спробувати й текстову вежу SigLIP для описів (але там лише 64 токени).
- Для злиття фото й тексту: менш агресивне стиснення (`IMG_PCA_DIM` / `TEXT_PCA_DIM` 64-128 або без PCA); невелика MLP на [ембединг фото, ембединг тексту, табличні ознаки] і бленд з LightGBM; косинусна схожість фото й опису (для CLIP / SigLIP) як окрема ознака.
- Більше фото: `MAX_IMAGES_PER_PET` 5 → 10; окремо ембединг головного фото (`-1.jpg`) поруч із середнім.
- Пороги вже окремі для кожної межі між класами. Можна ще усереднювати їх по фолдах чи seed-ах і порівнювати `ROUNDING = 'distribution'` з `optimized` на LB. На проксі-даних `optimized` був трохи кращий (0.424 проти 0.414).
- Порядкові голови: CORAL / CORN при донавчанні енкодера; або LightGBM multiclass → очікуване значення класу → ті самі пороги.
- Текст: інші моделі ембедингів (e5 / bge-m3 / xlm-roberta), донавчання DistilBERT / XLM-R на регресію; Ridge на TF-IDF як стекінг-ознака (обережно, лише OOF).
- Табличні ознаки (якщо є): `Fee / Quantity`, вік у роках, «чистокровність» (`Breed2 == 0`), назви порід і штатів з довідників `*_labels.csv`.
- Ансамбль: LightGBM + CatBoost + XGBoost з різними seed-ами (це звичайні моделі, не AutoML).
- Донавчання бекбону (EfficientNet / SigLIP) на регресію `AdoptionSpeed` на GPU Kaggle. Це найдорожчий крок, але потенційно найсильніший; треба зважати на квоту GPU.
